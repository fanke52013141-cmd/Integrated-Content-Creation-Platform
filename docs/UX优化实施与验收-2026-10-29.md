# UX 优化实施与验收（2026-10-29）

依据同日的《用户体验走查报告》（见 `artifacts/ux-report/用户体验走查报告-2026-10-29.md`）分三批落实优化：第一批覆盖报告中全部 4 个 P1 问题和 1 个低成本 P2 问题；第二批修复线上既有的 workspace 冒烟失败，并落实 3 个 P2 改进；第三批完成报告中的最后一项 P2-6（多候选逐个呈现）。除测试脚本外，改动集中在渲染层与 IPC 门禁，不涉及数据库结构。

## 第三批改动（P2-6）

### 10. 选题／框架多候选逐个点亮（P2-6）

- 文件：`src/renderer/src/hooks/useGenerationStream.ts`、`src/renderer/src/pages/TopicsPage.tsx`、`src/renderer/src/pages/FrameworksPage.tsx`
- 现状核实：主进程本就逐候选并发请求、每个候选完成即落库并发 `complete` 流事件；瓶颈在渲染层——两页只在整批结束后才 `refresh()`，用户面对整块等待。
- 改动：
  - `useGenerationStream.run()` 新增可选 `onCandidateComplete` 回调：每收到一个候选的 `complete` 事件即通知页面（600ms 节流，避免高频刷新）。
  - 选题页／框架页生成期间传入该回调做增量刷新；主进程按候选逐个落库，因此列表随生成进度逐张点亮，进度条（已完成 x/N）与列表同步。
  - 选题页在点击生成时即切到草稿视图（原为整批结束后才切换），用户能立刻看到候选到达。
  - 刷新失败静默容忍（生成中的增量刷新只是锦上添花，最终以任务返回后的全量刷新为准）。
- 验证：走查 mock 按候选序号错峰返回（第 N 个候选延迟 N×500ms），断言「首卡出现时生成仍在进行中」——选题与框架均实测在 `完成 2/3` 时列表已显示 2 张卡片（截图 `artifacts/ux-report/08-topics-generated.png`），旧实现此处为 0 张。

## 第二批改动（P2 与既有问题）

### 6. workspace 冒烟失败：确认为测试竞态并修复（线上既有问题）

- 文件：`scripts/smoke-workspace.mjs`
- 诊断：产品功能正常——诊断脚本（`artifacts/diag-workspace.mjs`）实测点击「定位正文」后 50ms 内选区稳定落在「2025 年」。失败原因是测试在点击后**同步**读取选区，而应用用 `requestAnimationFrame` 在下一帧设置选区，后台无头模式下测试读得比帧更早，读到空选区。
- 另发现 `.filter({hasText:'2025 年'})` 会同时匹配「12 篇」卡片的上下文摘要，卡片定位不精确。
- 修复：测试改为①按 `<strong>` 线索 token 精确锁定卡片；②等待选区真正出现（`waitForFunction`）后再断言。产品代码未改动。

### 7. 备份被拦时提示进行中的操作明细（P2-5）

- 文件：`src/main/services/operation-gate.ts`、`src/main/ipc.ts`、`tests/workflow-safety.test.ts`
- 问题：备份门禁只提示「还有操作进行中」，用户不知道在等什么、要等多久。
- 改动：门禁按通道记录进行中的操作，拒绝备份时给出明细（最多列 4 类，重复合并计数），如「还有 2 个操作进行中（配图生成 ×2），请等待它们完成后再备份或恢复」。通道映射为用户能看懂的名称（文章生成、配图生成、素材搜索等），未知通道回退为去前缀的通道名。

### 8. 批量生图费用确认支持「本次会话不再提示」（P2-7）

- 文件：`src/renderer/src/components/useConfirm.tsx`、`src/renderer/src/components/ConfirmDialog.tsx`、`src/renderer/src/components/VisualStudio.tsx`、`src/renderer/src/styles/base.css`
- 改动：确认弹窗组件支持可选的「不再提示」勾选（`suppressLabel`/`onSuppress`）；批量生图的费用确认接入——勾选后本次会话内跳过该确认，**应用重启后恢复确认**，避免静默扣费成为默认状态。

### 9. 配图工作台错误提示附一键重试（P2-8）

- 文件：`src/renderer/src/components/VisualStudio.tsx`
- 改动：`run()` 记录最近一次失败的操作，内联错误提示旁追加「重试「操作名」」按钮（如重试「生成／更新提示词」），操作成功后自动清除；用户不必在长表单里找回原按钮。

## 第一批改动（P1）

### 1. 首启弹窗增加明确的「先随便看看」退出（P1-1）

- 文件：`src/renderer/src/components/FirstCreationGuide.tsx`、`src/renderer/src/styles/pages.css`
- 问题：首启弹窗是强模态，退出只有右上角一个小 X（「稍后再说」），新用户想先浏览界面会被迫先做选择。
- 改动：弹窗底部操作区新增 ghost 按钮「先随便看看」，与「直接写草稿」并列；点击即关闭弹窗并停留在当前页，不导航。行为与 X 完全一致（标记引导完成）。

### 2. 新建草稿必填校验改为内联提示 + 聚焦缺失字段（P1-2）

- 文件：`src/renderer/src/pages/ArticlesPage.tsx`、`src/renderer/src/styles/articles.css`
- 问题：不选框架也不填手动框架时点「生成草稿」，只有一闪而过的 toast，无内联错误、不聚焦字段。
- 改动：
  - 校验失败在手动框架输入框正下方渲染常驻内联提示（`role="alert"`）：「还差写作基线：选择内容框架，或粘贴手动框架，二选一即可开始。」
  - 同时聚焦手动框架输入框并滚动到可见，输入框标红（`aria-invalid`）。
  - 「请选择可用模型」同样改为内联提示（保留原文案，兼容既有验收脚本 `scripts/ux-verify.mjs`）。
  - 用户修改框架／手动框架／模型任一项即清除提示；关闭弹窗（取消／X／遮罩）时一并重置。
  - toast 不再用于这两类必填校验（成功与失败提示仍走 toast）。

### 3. 账号名过长时就地提醒精简（P1-3）

- 文件：`src/renderer/src/pages/AccountPage.tsx`、`src/renderer/src/styles/pages.css`
- 问题：用户常把整句想法当作账号名（或 AI 沿用），锁定后该长名会出现在创作、发布等多处。
- 改动：定位字段中「账号名称」在未锁定且内容超过 20 字时，字段下方显示提醒「账号名较长，建议精简成好记的名字再锁定，它会显示在创作和发布各处。」；修改后即时消失。

### 4. 配图工作台：生图模型缺失时给出解释与一键跳转（P1-4）

- 文件：`src/renderer/src/components/VisualStudio.tsx`
- 问题 A：没有任何生图模型时（供应商未勾选「图片生成」能力，或未选模型），第 3 步批量按钮静默禁用。
- 改动 A：第 3 步在批量按钮上方显示内联提示「还没有选择生图模型，批量生成暂不可用。」并附「回到第 1 步选择生图模型」按钮（点击切换到方案阶段）。提示与按钮同条件渲染（`!imageTarget`），只在第 3 步可见（复用 `studio-image-section` 的阶段显隐规则）。
- 改动 B：生图模型下拉为空时，空态文案由「暂无选项」改为「还没有可用的生图模型：到「AI 服务」给供应商勾选「图片生成」能力后，模型会出现在这里」。
- 说明：存在可用生图模型时 `useModelTarget` 会自动选中第一个，常见路径不受影响；本次改动只补「确实没有模型」时的引导。

### 5. 素材搜索空态说明与入口更明确（P2-9）

- 文件：`src/renderer/src/pages/MaterialsPage.tsx`
- 改动：「搜索服务未配置」空态补充说明（配置豆包搜索密钥后可联网搜网页/图片并入库），按钮文案由「去配置」改为「去配置搜索密钥」。

## 已知限制

- 账号名提醒阈值（20 字）为经验值，未做用户测试校准。
- 增量刷新节流间隔 600ms 为经验值；候选间隔小于该值时仍会合并刷新，不影响最终一致性。
- 「本次会话不再提示」的记忆为渲染进程内存态，应用重启后按设计恢复确认。
- 真实公众号通道（草稿箱推送）仍需持有 AppID／IP 白名单时专项验收。
