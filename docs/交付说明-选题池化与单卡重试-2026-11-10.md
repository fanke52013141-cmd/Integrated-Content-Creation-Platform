# 交付说明：选题池化与单卡重试（批次 3，2026-11-10）

> 上游方案：[优化方案-全量待办与分期计划-2026-11-09](优化方案-全量待办与分期计划-2026-11-09.md) 批次 3（P0-2）。
> 落实 PRD-选题AI §4.4 的账号池/关键词池机制与 §4.5 单卡重试。数据层 `Topic.accountIds` 原本就是数组，本批无 DB 迁移。

## 范围

**选题池化（契约/服务/IPC/UI）**
- `GenerateTopicsInput`：`accountId → accountIds[]`（0~10 个，均须锁定，空=通用创作）、`seedKeyword → seedKeywords[]`（1~10 个）、新增 `mode: 'round-robin'（默认）| 'exhaustive'`。
- 分配算法：轮询按 `i % 账号数`、`i % 关键词数` 交错取模；穷举展开账号 × 关键词 × count 笛卡尔积，服务端硬上限 60 条（超出拒绝并提示）。
- 历史去重按每次任务对应账号过滤（池化后按账号缓存一次查询）；失败项携带当次的 `accountId/seedKeyword` 分配快照。
- TopicsPage：账号改多选 chips；主题输入每行一个关键词（单行行为与旧版一致）；池大于 1 时出现「轮询/穷举」分配开关；生成按钮实时显示预估产物数（穷举 >30 时二次确认）；失败列表每条带「重试」按钮，按原分配原位重跑。

**单卡重试（选题 + 框架）**
- 新增 `topics:retry-one`（按失败项分配快照重跑单条）与 `frameworks:retry-one`（沿用当次面板输入 count=1 重跑）；对齐文章模块已有的恢复能力。
- FrameworksPage 失败提示行增加「按当前输入重试一个」。

## 验证

- `npm run typecheck` 通过；`npm test` 510/510 全绿（`batch-failure-isolation.test.ts` 新增 4 例：轮询分配矩阵、穷举组合覆盖与上限、失败快照 + retryOne、框架 retryOne；既有用例迁移到池化入参）。
- `npm run test:topics`、`npm run test:frameworks` 冒烟通过（构建 + Electron）。

## 已知边界

- 穷举模式下选题页的实时预估与确认阈值（30）低于服务端硬上限（60）：前端先拦一次，服务端兜底。
- 单行关键词输入的旧草稿（localStorage `topic-seed`）直接兼容：单行 = 单元素池。

## 回滚

- 无数据迁移。`git revert` 本提交即可；契约为破坏性变更（单数 → 复数），回滚时需整体回滚本批的契约/服务/UI/测试改动。
