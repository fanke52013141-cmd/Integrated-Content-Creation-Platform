# 心流 · 交互优化方案（减少重复操作 × 补齐体验断层）

> 日期：2026-08-29 · 依据：《审查报告-流程与UI》 + 全流程用户走查
> 目标：在不改变「每步人工确认（HITL）」产品原则的前提下，把一次完整创作流程的手工操作减少约 40~50%，并消除跨页面的状态丢失与信息断层。
> 分三个批次实施：P0（低成本高收益，先做）→ P1（中成本核心体验）→ P2（可选打磨）。

---

## 批次一（P0）：立刻省掉一半重复操作

### 1.1 全局默认模型 —— 模型从「选 7 遍」变「选 0 遍」
**问题**：热点筛选、选题、框架、文章、评审、配图方案、生图各自维护 `modelTarget`，每进一个页面都要重选一次（`TopicsPage/FrameworksPage/ArticlesPage/ReviewsPage/VisualsPage/HotspotsPage` 各自的 state）。

**方案（写穿式记忆，不加新 UI）**：
- 扩展 `src/renderer/src/lib/models.ts` 的 `useModelTarget(models, storageKey = 'moliu:default-model')`：
  - 初始化时读 localStorage，无值再回落到「供应商默认模型」；
  - 用户在任何页面改动模型时，同步写回 localStorage（最后使用 = 全局默认）。
- 生图模型用独立键 `moliu:default-image-model`（`VisualsPage` 的 `imageTarget`）。
- 把 `HotspotsPage` 的 `filterModelTarget` 从本地 state 迁移到 `useModelTarget`。
- 效果：配过一次后，所有页面自动带出；换模型只需改一次，全局生效。

**涉及文件**：`lib/models.ts`、六个页面（多为删代码）。
**工作量**：0.5 天 · **风险**：无（纯前端，键值可随时被用户覆盖）。

### 1.2 Composer 草稿本地暂存 —— 切页不再丢输入
**问题**：路由切换即卸载页面组件，选题关键词、手动框架/主题、改稿指令等填了一半的内容全部丢失（`App.tsx` 条件渲染 `{route === 'x' && <XPage/>}`）。

**方案**：
- 新增 `src/renderer/src/hooks/useDraftState.ts`：签名同 `useState`，初始化读 `localStorage['moliu:draft:<key>']`，变化即写入（含清空），提供 `clear()`。
- 接入四个高价值字段：
  - `TopicsPage.seedKeyword` → `moliu:draft:topic-seed`
  - `FrameworksPage.manualTopic` → `moliu:draft:framework-topic`
  - `ArticlesPage.manualOutline` → `moliu:draft:article-outline`
  - `ArticlesPage.instruction`（改稿指令）→ `moliu:draft:article-instruction`
- 提交成功后调用 `clear()`（生成成功/保存成功时）。

**涉及文件**：新 hook + 3 个页面各 2 行。
**工作量**：0.5 天 · **风险**：无。

### 1.3 热点 → 选题关键词自动预填
**问题**：热点页「生成选题」只传收藏 id（`moliu:topic-favorite-ids`），选题页关键词框为空，用户要手抄热点标题。

**方案**：
- `HotspotsPage.openTopicsFromFavorites` 同时写入 `moliu:topic-seed-keyword`（取前 3 条收藏标题，用「；」拼接，超 200 字截断）。
- `TopicsPage` 挂载时读取（读取即清除，与现有 favorite-ids 同模式），仅当关键词框为空时预填。

**涉及文件**：`HotspotsPage.tsx`、`TopicsPage.tsx`。
**工作量**：0.25 天 · **风险**：无。

### 1.4 Ctrl+Enter 触发生成
**方案**：`TopicsPage/FrameworksPage/ArticlesPage` 的主输入框（关键词/主题/手动框架/改稿指令 textarea）`onKeyDown` 捕获 `Ctrl/Cmd+Enter` 调用各自的 generate/revise（复用按钮的 disabled 条件）。快捷键面板已有该项说明，无需改文案（改回「触发 AI 生成」）。

**工作量**：0.25 天。

### 1.5 评审冷启动：内置默认评审角色
**问题**：第一次进评审页角色为空，只有一个文字链接，用户不知道角色指令怎么写，流程卡死。

**方案**：`database.ts` 增加 `ensureReviewRoles()`（挂到 `migrate()` 尾部，表空时种子 3 个角色，与 `ensureFrameworkTemplate` 同模式）：
1. **结构编辑**：检查逻辑主线、段落衔接、详略与节奏；
2. **标题与开头**：以点击率视角审标题与前三句的钩子；
3. **事实核查**：标出无依据断言、数据与引用风险。
默认使用全局 fallback 模型（不绑定 provider），extractionTag 沿用「评审意见」。

**涉及文件**：`database.ts`、`contracts.ts`（无新字段）。
**工作量**：0.5 天 · **风险**：低（幂等种子；老库不受影响）。

### 1.6 发布页自动预填 + 公众号后台直达
**问题**：换一篇文章推送，作者/摘要每次重填；推送成功后要自己找 mp.weixin.qq.com 入口。

**方案**：
- `App.tsx` 给 `PublishingPage` 传 `currentAccount`；作者默认 = 当前账号名（可改）。
- 摘要默认 = 所选排版稿对应文章的第一段（去 Markdown 标记、截 120 字），仅在字段为空时预填。
- 推送成功后，发布记录行内（status=draft）增加「打开公众号后台 →」按钮，复用现成的 `window.moliu.hotspots.openSource('https://mp.weixin.qq.com/')`（走 `shell.openExternal`，无需新 IPC）。

**涉及文件**：`App.tsx`、`PublishingPage.tsx`。
**工作量**：0.5 天 · **风险**：无。

### 1.7 模型网关配置后一键返回
**问题**：点网关 banner 去配置，配完要自己摸回原页面。

**方案**：banner `onNavigate('providers', { returnTo: route })`；`ProvidersPage` 新增 `onNavigate` prop，保存供应商成功且带 `returnTo` 时弹 toast「已连接，返回继续」并自动跳回。`App.tsx` 读取 searchParams 传入。

**工作量**：0.25 天。

## 批次二（P1）：核心体验升级

### 2.1 配图批量生成与批量上传 —— 16 次点击 → 2 次
**问题**：一套方案（1 封面 + N 文内 + 3 发布）要逐张点「生成图片」再逐张点「上传公众号」。

**方案（前端循环驱动，复用现有互斥与单张接口）**：
- `VisualPackCard` 头部加两个按钮：「生成全部图片」「全部上传素材库」。
- 生成：按 封面 → 文内 → 发布 顺序逐张调用 `visuals.generateImage`（每张间无需延时，串行即可）；批量期间每张槽位显示单张进度，卡片头部显示总进度「3/8」，提供「停止批量」（置一个 ref 标记，当前张完成后停止；当张可被 `generation.cancel('visuals')` 取消）。
- 上传：遍历无 `wechatMediaId` 的资产逐张调用 `publishing.uploadWechatCover`，失败的单张标记并在结束后汇总 toast（成功 x / 失败 y）。
- 已有图片的槽位自动跳过（增量化，重复点击无副作用）。

**涉及文件**：`VisualsPage.tsx`（无后端改动）。
**工作量**：1 天 · **风险**：低（批量中生图模型额度按张消耗，需在按钮 tooltip 说明）。

### 2.2 全局任务状态与完成通知 —— 生成「离开即失联」问题
**问题**：流式预览只在页面内，切走后完成/失败完全无感知。

**方案（主进程广播 + App 全局订阅）**：
- 后端：`ipc.ts` 中每个被 `beginGeneration/endGeneration` 包裹的 handler，在 try/finally 里通过新通道 `generation:events` 发送 `{ domain, status: 'started' | 'done' | 'failed', message? }`（`sendToStream` 已具备销毁保护）。
- `contracts.ts`：`generation.events(onCallback): () => void`；`preload`、`mock-bridge` 同步。
- `App.tsx`：全局订阅；顶栏（breadcrumb 右侧）显示运行中任务 chip「⏳ 正在生成选题…」（domain → 中文名映射复用 PipelineSteps 的常量）；任务结束弹 toast（成功「选题生成完成」，失败带错误摘要）。多任务并行时 chip 显示数量 + 最近一条。
- 页面内流式预览保持不变（两层互不干扰）。

**涉及文件**：`ipc.ts`、`contracts.ts`、`preload/index.ts`、`mock-bridge.ts`、`App.tsx`、新组件 `components/GenerationStatus.tsx`。
**工作量**：1.5 天 · **风险**：低（新增只读通道，不影响现有流）。

### 2.3 文章页素材自动沿用框架
**问题**：框架勾了素材，文章页要重新想一遍（现有逻辑仅首次且本地为空时带入一次）。

**方案**：`ArticlesPage` 的框架选择 effect 改为：`frameworkId` 变化且新框架带素材时，直接覆盖 `materialIds` 为框架素材，并在素材选择器上方显示一次性提示「已沿用框架的 N 条素材 · 修改」。手动清空后不强制恢复（尊重用户）。

**工作量**：0.25 天。

### 2.4 文章 / 选题列表搜索
**方案**：`ArticlesPage` 列表头与 `TopicsPage` wall 头部各加一个 `search-field` 过滤框（标题子串匹配，纯前端 filter， VirtualList items 传入过滤结果）。文章额外按「已锁定/草稿」快速筛选 chip。

**工作量**：0.5 天。

## 批次三（P2）：可选打磨

### 3.1 素材搜索结果批量入库
`MaterialsPage` 搜索结果头部加「前 10 条全部入库」按钮（循环 `addSearchResult`，跳过已入库，结束 toast 汇总），与热点的批量收藏对齐。

### 3.2 首次启动引导
首启（无账号且无供应商时）在账号页空态下方展示三步引导条：① 配置模型网关 → ② 创建并锁定账号 → ③ 去热点收藏。全部完成后自动消失。价值中等，建议观察批次一/二上线后的反馈再定。

### 3.3 发布记录改进（已含在 1.6，此处备忘）
草稿行增加「复制草稿链接」、失败行显示可读错误码解释（后端 `wechatErrorMessage` 已返回，确保 UI 完整展示而非截断）。

## 不做的事（明确排除）
- **自动串联生成**（锁定选题后自动生成框架等）：与 HITL 原则和「锁定」语义冲突，保持「下一步」引导按钮形态。
- 富文本编辑器重写、SQLite 移出主线程、小红书发布：维持审查报告结论，另立项目。

## 实施与验收

**顺序**：批次一（约 2.75 天）→ 批次二（约 3.25 天）→ 批次三按需。每批次结束跑 `npm run build` + vitest；涉及页面的改动用 `scripts/ui-screenshots.mjs` 重截图做视觉回归；新增 IPC 同步更新 `mock-bridge.ts` 保证浏览器预览可用。

**手工验收清单（批次一完成后）**：
1. 任一页面选一次模型 → 其余 6 处自动带出；
2. 选题页填关键词 → 切热点页再回来 → 关键词还在；
3. 热点页「生成选题」→ 选题页关键词已预填收藏标题；
4. 全新数据库启动 → 评审页直接有 3 个可勾选角色；
5. 推送草稿 → 作者/摘要已预填，记录行可一键打开公众号后台；
6. 生成期间切页面 → 顶栏出现任务 chip，完成后收到 toast。

**风险与回滚**：全部改动不涉及 DB schema（除幂等角色种子，空表才写入）；新 IPC 均为只读/可选通道；localStorage 键互相独立，任一项可单独回滚。
