# 逐页接设计稿 · 计划与进度（2026-10-18）

## 一、先说清楚「接成前端代码」是什么

Stitch 生成的 14 张设计稿是**静态 HTML**（Tailwind CDN + 写死的文案与假数据），
而应用是 React + IPC 的真实数据流。所以「接」不是把 HTML 贴进来，而是：

> 把每张稿子的**页面骨架**（页头、栏宽、卡片区头、行高、留白）落到现有页面的 JSX/CSS 上，
> 同时保留全部交互与数据逻辑。

整件事是 14 页 × 若干处结构调整，属于多轮工程，不适合一把梭——一把梭会同时动 30+ 组件，
一旦观感不对很难回退。

## 三、本轮的样板改动（13 数据与备份）

- `.data-workspace`：两栏 grid → **单列 flex，最宽 880px**；
- 侧栏两张卡用 `display: contents` 并入主列，形成**三张卡纵向排列**；
- 区头统一 **56px**、标题 17px、副文案 12px；
- 备份行 **44px**（图标 32、上下 6px）；
- 空状态高度 320 → 240，标题 18 → 15px。

实测：工作区 880×660，三张卡 201 / 154 / 231，区头 56，行高 47–48，横向溢出 0。
截图：`artifacts/ui-walk-2026-10-18/after-data/13-data.png`。

## 四、验收方式（每页都走同一套）

1. `node artifacts/ui-walk-2026-10-18/check-page.mjs <route>`：量栏宽、区头、行高、溢出；
2. `node artifacts/ui-walk-2026-10-18/verify.mjs <tag>`：14 页的重叠 / 碰撞 / 对比度；
3. `node artifacts/ui-walk-2026-10-18/shots.mjs <tag>`：截图留档；
4. `tsc` + `electron-vite build` 必须通过。

## 五、限制（必须说明）

我当前模型**不接受图像输入**，所以「精修观感」这一步我只能保证结构、尺寸、间距、对齐、
对比度这些可测项；「好不好看」必须由人看截图定稿。每轮我会给出截图目录，方便你抽查。
