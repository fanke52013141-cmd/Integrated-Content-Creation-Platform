## 三、AI 生成链路验收（重点）

这是产品的核心价值，因此单独做了带mock 模型服务的端到端验证，并**直接查数据库核验落库结果**。

### 选题生成：✅ 完整成功

| 环节 | 实测 |
| --- | --- |
| 请求发出 | ✅ 模型被调用 6 次（3 条选题并行） |
| 解析成功 | ✅ UI 不再显示空态 |
| **落库** | ✅ `topics` 表 **3 行**，含 `seed_keyword`、`account_ids_json`、`status=draft` |
| **任务台账** | ✅ `generation_tasks`: `domain=topics, status=succeeded` |

### 框架/文章生成：请求已发出，因 mock 不符协议而未落库

| 环节 | 框架 | 文章 |
| --- | --- | --- |
| 前置校验 | ✅ 通过（模板已选、主题已填） | ✅ 通过（手动框架已填） |
| 请求发出 | ✅ 模型被调用 6 次 | ✅ 模型被调用 2 次 |
| 落库 | ❌ 0 行 | ❌ 0 行 |
| 任务状态 | `partial` | `partial` |

**这不是产品缺陷，是 mock 不符合协议。** 证据：

- 框架解析函数 `parseFrameworkXml`（`framework-generator.ts:143`）要求模型返回 `<框架>...</框架>` **XML 标签结构**，我的 mock 返回的是 Markdown。
- 文章同理，`extractTaggedBlock` 约定用标签块承载内容。

**产品的要求是合理的** —— 结构化输出比自由文本可靠得多，解析失败时明确标记 `partial` 而不是静默产出脏数据，这是**正确的错误处理设计**。

### 一个真实的可观测性缺口

`model_calls` 表在验收中始终为空。排查后确认：

- `recordModelCall()` 有 5 处调用（`model-gateway.ts:168/192/262/286/340`）
- 但**流式请求路径（`streamChat`，417 行起）完全没有记录**

而**生成功能全部走流式**，所以真实用户的每次生成都不会被记录。

| 影响 | 程度 |
| --- | --- |
| 用户能否正常使用 | ❌ 不影响 |
| 能否看到生成历史 | ❌ 不影响（`generation_tasks` 表承担了这个职责） |
| 能否统计 token 消耗 / 模型费用 | ⚠️ **不能** |

**建议**：发布后补一行 `recordModelCall` 到流式路径收尾处。这是内部可观测性问题，不构成发布阻塞。

## 四、值得肯定的设计（整改时请勿破坏）

验收中遇到多次"失败"，逐一查证后**全部是正确的产品设计**，不是 bug：

| 现象 | 实际是|
| --- | --- |
| 未锁定账号时选题页显示「还没有已锁定的账号定位，无法发起有基线的选题生成」+「去锁定账号」按钮 | ✅ 主动拦截 + 明确出口 |
| 框架页提示「请选择选题，或填写框架主题」 | ✅ 防呆校验 |
| 文章页提示需选框架或填手动框架 | ✅ 防呆校验 |
| 框架未选模板时提示「请选择框架模板」 | ✅ 前置校验 |
| 网关未验证连通不允许保存 | ✅ 防止「配好了却用不了」 |
| 任务状态 `partial` 而非静默失败 | ✅ 真实反映结果 |

这套「缺前置条件就拦下并告诉用户缺什么、怎么补」的模式，**是这次验收里最值得保留的设计**。

## 六、发布建议

### 可以现在发布给谁

| 用户类型 | 是否建议 |
| --- | --- |
| **自己 / 团队内测** | ✅ 建议立即发布（记得先重打包） |
| **少量种子用户（< 20 人）** | ✅ 建议发布，但需告知「AI 效果取决于所配模型」 |
| **公开发布 / 大量用户** | ○ 建议先补流式调用的 token 统计（第三节），并明确「模型由用户自备」 |

### 需要在发布说明里写清的

1. **需自备模型**：应用不含模型额度，用户须自行配置任一 OpenAI 兼容服务（豆包/DeepSeek/OpenAI 等）的地址与密钥。
2. **数据全在本机**：所有稿件、账号、密钥都存在本地 `moliu.db`，不上传云端。换机需手动迁移。
3. **前置条件**：AI 生成需先锁定账号定位；框架/文章生成需先选模板并填主题或选题。
4. **已知限制**：token 消耗暂不支持统计（内部缺口，不影响使用）。

## 七、复现方式

```bash
cd "D:\Program Files (x86)\Integrated-Content-Creation-Platform"

# 真实 Electron 启动（必须清ELECTRON_RUN_AS_NODE）
unset ELECTRON_RUN_AS_NODE
node acceptance-test.mjs        # 15 项全链路验收
node db-check.mjs               # AI 链路 + 落库核验

# 前 5 个需先npm run build
node ux-audit-metrics.mjs       # 对比度/点击目标/字号
node verify-nav.mjs             # 导航一致性
node verify-flow.mjs            # 流程顺畅度
```

**环境要点**（不设则启动失败）：

```js
delete process.env.ELECTRON_RUN_AS_NODE   // 否则 Electron 走纯 Node 模式，报 BrowserWindow 导出错误
args: ['--disable-gpu', '--disable-software-rasterizer', '--no-sandbox']  // 无 GPU 环境必需
```

### mock 模型服务的协议要求（踩坑记录）

若要自建 mock 测 AI 链路，**必须遵守产品协议**，否则会误判为产品缺陷：

| 阶段 | 期望格式 | 解析函数 |
| --- | --- | --- |
| 选题 | JSON 对象，**键集合须与字段定义完全一致**（默认 7 个：选题主题/切入角度/目标读者/核心观点/情绪基调/拟标题方向/备注） | `parseTopicJson` |
| 框架 | `<框架>...</框架>` XML 标签结构 | `parseFrameworkXml` |
| 文章 | 标签块（`extractBlock`约定） | `extractTaggedBlock` |
