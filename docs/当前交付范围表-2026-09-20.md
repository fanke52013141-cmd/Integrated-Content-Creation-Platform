口径按《用户创作体验审查与优化方案-2026-09-20》§11 要求，每项只标四种状态之一：

- **已实现**：代码与数据链路已落地，但本轮没有端到端跑过。

回归自身也修掉几处假阳性/脆弱点，其中两处是顺带发现的真实产品缺陷：
- **热榜平台拖拽排序偶发丢失（产品缺陷）**：`HotspotsPage` 的「平台设置」把正在拖拽的平台 id 放在 React state 里，`dragstart` 触发的 `setState` 还没提交，`drop` 就已经跑完，回调闭包里读到 `undefined` 于是静默放弃换位——机器空闲时看不出问题，批量回归有负载时必现（`smoke-hotspots` 报「期望 douyin | 36kr·隐藏 | weibo，实际 36kr·隐藏 | douyin | weibo」）。现改为同步写 `draggingSourceIdRef`，state 只用于高亮样式；顺带删掉从未被调用的 `reorderWallSource()` 与整份 `components/SourceManagerDialog.tsx`（与页面内联实现逐字重复、带同样的缺陷，留着必然两边漂移）。
- **截图超时把通过的功能误判成失败**：证据截图原先各自写 `window.screenshot()`，默认 30s 超时，且 `smoke-hotspots` 的 `catch` 分支里那张诊断截图自己超时后会直接顶替原始错误（第一个失败批因此看不到真因）。现统一走 `scripts/lib/evidence.mjs` 的 `capture()`：关掉动画、90s 超时、退避重试 4 次，重试用尽仍抛错，证据不会静默丢失；`catch` 改为先 `console.error(error)` 再截图并单独兜住截图失败。
- `smoke-hotspots` 的拖拽断言不再硬编码「第一条移到第二条之后」，而是先读界面顺序、以「界面前后确实换位」为断言（最多重试 3 次），再拿这份界面顺序核对落库结果，Playwright 原生拖拽模拟偶发不落地不再被误读成产品缺陷。
- `smoke-topics` 原先 `getByText('条选题草稿')` 会命中页面静态说明文案，等于没断言（只有 toast 还在时才会因 strict mode 报错，所以表现为“偶尔失败、单跑必过”）。现改为精确匹配 toast 并断言候选卡片数恰为 2。
- `smoke-workspace` 在批量顺序运行且机器同时跑其他任务时，弹窗截图曾超过 Playwright 默认 30s；截图超时不代表功能失败，已放宽到 90s。批量回归期间不要再并行执行构建或网络任务。
