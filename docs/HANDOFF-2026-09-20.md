## 四、怎么自己验一遍（顺序很重要）

```bash
npm run typecheck     # 两个 tsconfig 都要绿；注意 scripts/ 不在 typecheck 覆盖范围内
npm test              # 17 文件 / 112 例
npm run build         # typecheck + electron-vite build
node scripts/run-all-smokes.mjs   # 11 路端到端，单套件 5 分钟超时，任一失败非零退出
```

`npm run test:smokes` 等价于"先 build 再跑整轮"。单套件：`npm run test:articles`（含 build），或跳过 build 直接 `node scripts/smoke-articles.mjs`。

冒烟约定（踩过的坑，务必遵守）：

- 每个套件用 `MOLIU_USER_DATA_DIR` 指到独立临时目录，外部网络（真实热榜、豆包、微信）一律以本地假接口替代——**因此冒烟绿不等于外部联调通过**。
- 证据截图统一走 `scripts/lib/evidence.mjs` 的 `capture()`：关动画、90s 超时、退避重试 4 次。不要写裸 `page.screenshot()`，默认 30s 超时会在批量负载下把**通过的功能**误判成失败。
- `catch` 分支里先 `console.error(error)` 再截图，并单独兜住截图失败。上一轮就因为诊断截图自己超时，把真错误顶掉了。
- 批量回归期间**不要并行**跑 build、测试或任何网络任务；不要把批量输出接管道给 `tail`（会吞掉真实退出码）。
- 断言要从 DOM 读出来再核对（比如拖拽后先读界面顺序，再拿这份顺序核对落库），不要硬编码"点第 1 条移到第 2 条之后"这种理想顺序。
- `getByText` 的 substring 若同时命中页面静态说明文案，等于没断言：用精确匹配或限定容器。
- React 19 下 `useRef` 必须给初值：`useRef<string | undefined>(undefined)`。
- 改完界面布局要看一张截图确认，别只断言 DOM 存在（版本行按钮换行就是这么漏出去的）。
