## 二、流程现状

```
账号(可选) → 热点(可选) → 选题 → 框架 → 文章 → 评审(可选) → 配图 → 排版 → 发布
        └─ 任意环节可经「标准导入」直接进入（2026-11-27 新增）
```

流程定义集中在 `src/shared/creation-flow.ts`，侧栏、顶部流水线、作品栏共用同一份，不再有顺序冲突。作品栏有「下一步」按钮。

## 四、现存阻塞点与风险

### 🔴 B1 · 封面依赖链是新用户最可能卡住的地方
- 发布预检强制要求封面（`wechat-publish-service.ts:113`）：必须有封面图或 `thumbMediaId`。
- 「配图」在流水线里不是可选阶段，但没有图片模型时，只能手动导入本地图片。
- 用户走到发布才发现缺封面，要退回配图页；预检提示是文字，是否带「去配图」跳转需确认。
- **建议**：① 进入排版或发布前，在作品栏提示「尚无封面」；② 预检失败项附带跳转按钮；③ 配图页检测到没有图片模型时，直接给出「导入本地图」入口说明。

### 🟠 B2 · 正文一改，排版稿就作废，只能手动重排
- 发布预检：`layout.articleVersionId !== article.currentVersionId` 即报「请重新排版」（`wechat-publish-service.ts:~125`）。
- 排版页和发布页都只显示提示条。评审「应用改稿」会生成新版本，因此「评审 → 改稿 → 重新排版 → 重新选封面确认」会反复出现。
- **建议**：提示条加「基于最新正文重新排版」一键动作；发布页检测到过期直接跳排版并带参数。

### 🟠 B3 · 非微信平台是断头路
- 排版支持 `wechat | xiaohongshu | web`（`contracts.ts:842`），但发布只通微信公众号（含「小绿书」图片消息）。
- 小红书/网页排版稿只能复制导出，流水线「发布」阶段对它们没有意义。
- **建议**：在选择平台时明示「该平台仅导出，不含发布」，或让流水线第 9 步在非微信时显示为「导出」。

### 🟡 B4 · 可选环节没有「跳过」的表达
- 评审为可选，但作品栏「下一步」从正文固定指向评审（`WORKBAR_STAGES` 顺序）。想直接配图需要走侧栏。
- **建议**：下一步旁增加「跳过评审，去配图」次级按钮，或按 `optional` 字段自动提供。

### 🟡 B5 · 按模块互斥会让用户无谓等待
- 同一模块（如 `articles`）同时只能一个任务：生成、改稿、续写、重试共享一把锁。长文生成期间不能同时做另一篇的改稿，错误文案是「该模块已有生成任务进行中」。
- 这是有意的安全设计，但没有说明哪个任务在占用。
- **建议**：冲突提示里带上正在运行的任务名和「取消」入口（任务台账已有数据）。

### 🟡 B6 · 微信发布链路最后一公里仍有手工步骤
- 推送只到公众号**草稿箱**，正式发表要在公众号后台；`unknown` 状态要用户去后台核对再点「核对发表结果」。
- 这由微信接口和账号权限决定，属可接受限制。**需要在交付预览页写明**，避免用户以为已发表。

### 🟢 B7 · 工程层面
- 单测整套并行时有 1 个耗时敏感用例会偶发失败，会让 CI（`.github/workflows/verify.yml`）出现假红。建议给该用例加超时或避开并行。
- `ipc.ts` 里 `reviews:*`、`visuals:*` 等 handler 仍是压成单行的代码（如 `ipc.ts:1015`），难维护，但不影响运行。
- `database.ts` 约 16 万字节，单文件过大，属维护风险。
- 主进程使用同步 SQLite（`node:sqlite`），在大库上长查询可能卡 UI，目前量级可接受。
- 未跟踪文件 `.dsh-ops/`、`.stitch/*` 是工具产物，建议加入 `.gitignore`。

## 五、各环节顺畅度

| 环节 | 评价 | 备注 |
|---|---|---|
| 账号 → 热点 | 顺畅 | 两者均可选，热点 AI 筛选有进度事件 |
| 选题 | 顺畅 | 必须使用「已锁定」账号定位（`topic-generator.ts:31`），未锁定的报错需有明确引导 |
| 框架 → 文章 | 顺畅 | 可取消、可流式、可续写 |
| 评审 | 顺畅 | 需先保存正文（`assertSaved`）；评审绑定文章版本，改稿后旧评审会标记过期 |
| 配图 | 有条件 | 见 B1 |
| 排版 | 有摩擦 | 见 B2、B3 |
| 发布 | 有条件 | 见 B1、B2、B6；预检、快照、重试、`unknown` 防重机制设计较好 |
| 导入任意环节 | 顺畅 | 11-27 新增，覆盖 CSV/MD/DOCX/HTML，有模板下载 |

## 六、优先级建议

1. **B1 + B2**：预检失败项做成可跳转，过期排版一键重排。改动小，直接减少用户最常见的往返。
2. **B3 + B4**：补充流程语义表达，成本很低。
3. **B5**：冲突提示带任务名。
4. **B7**：修测试 flaky，避免 CI 假红。
