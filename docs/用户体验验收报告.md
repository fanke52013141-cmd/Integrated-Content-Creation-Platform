# 心流 Desktop · 用户体验验收报告

>验收方式：真实 Electron 启动，模拟「第一次使用这个产品的普通用户」
> 验收时间：2026-10-05
> 验收对象：心流 Desktop v0.1.0（`release\心流-0.1.0-setup.exe`）

---

## 1. 一句话体验结论

**产品做得比我预期的扎实，但三个"按钮灰着却不告诉你为什么"的地方，会让新手在每个环节都卡一下——它们不致命，却让人怀疑是不是自己用错了。**

## 4. 真实用户体验路径

按实际发生顺序记录：

**① 打开应用**
→ 首屏是「创作台」，顶部一条醒目提示「第一步：连接一个文本模型」+ 右侧按钮「去 模型网关」
→ 下方四个入口卡片（从主题开始 / 从热点开始 / 从资料开始 / 导入现成文章）
→ ✅ **我知道第一步该做什么**，没有迷路

**② 点「去模型网关」**
→ 表单很长，但顶部有 8 个厂商快捷标签（OpenAI / DeepSeek / Kimi / 智谱GLM / 豆包 / 腾讯云开言 / 自定义中转站）
→ 密钥旁明确写「暂不保存」、底部写明数据目录位置
→ ⚠️ 我不确定「模型标识」该填什么——**但我发现点厂商标签会自动填**，这个设计救了我
→ ✅ 保存成功，有「测试连接」按钮且测试通过才允许保存

**③ 建账号定位**
→ 向导模式：写一句想法 → AI 追问 → 可跳过 → 手动填字段
→ 跳过 8 问后进入字段页，看到 **9 个空白字段**，右上角显示「完整度 11%」
→ ⚠️ **我不知道最少填几个才能用**，也不确定哪几个最重要

**④ 写文章**
→ 侧边栏 13 个页面，顶部流水线「账号→热点→选题→框架→文章→评审→配图→排版→发布」
→ 点「导入现成稿」粘贴 Markdown → ✅ 编辑器正常，**不配模型也能用**（这是重要兜底）

**⑤ 评审**
→ 看到文章、模型已选，下面三个角色复选框（结构编辑 / 标题与开头 / 事实核查）**默认都没勾**
→ 「开始评审」按钮是**灰色不可点**
→ ❌ **页面上没有任何文字告诉我"要先勾选角色"**，我以为是坏了

**⑥ 配图**
→ 橙色提示条：「尚未配置生图模型…也可以逐张导入本地图片」+给了替代路径
→ ✅ **这里是全产品最好的空态设计**

**⑦ 排版**
→ 选文章、平台（微信公众号）、主题 → 「生成排版稿」
→ 空态提示：「选择平台后点击「生成排版稿」」
→ ⚠️ 但按钮的禁用条件其实是**没选文章**，不是没选平台。**文案在指错方向**

**⑧ 发布**
→ 三步结构清晰：连接公众号 → 推送草稿箱 → 发布记录
→ 顶部橙色条：「还没有可发布的排版稿：先在「文章排版」生成一份公众号排版稿」
→ ✅ 阻塞提示准确

---

## 5. 做得好的地方（这些请务必保留）

**① 「不配模型也能用」的兜底设计**
导入现成稿 → 编辑器 → 排版，这条路径完全不依赖 AI。我是在测「模型没配好」时才发现它的——这是很多同类产品没有的。它让产品在任何网络/额度故障下都还能用。

**② 阻塞提示会说清「缺什么、去哪弄」**
「还没有已锁定的账号定位，无法发起有基线的选题生成」+「去锁定账号」按钮
「尚未配置生图模型…也可以逐张导入本地图片」
「还没有可发布的排版稿：先在「文章排版」生成一份」
——这三条都是**明确的因果 + 明确的下一步**，比只说「暂无数据」强太多。

**③ 数据透明与安全说明**
密钥「暂不保存」、数据目录路径可见、支持立即备份。关掉编辑器自动保存草稿也提示了。这在桌面端里是加分项。

**④ 当前作品栏解决了"接着上次写"**
顶部常驻「体制内备考经验贴 · 第 1 版 · 已锁定」，跨页面切换不丢上下文。这是我在测试中偶然发现的惊喜。

**⑤ 厂商快捷标签自动填模型标识**
新手最怕的"我不知道该填什么"，点一下豆包/DeepSeek 就自动填好了。这个设计很懂新手。

## 6. 最大的 3 个问题

### 问题一：三个灰色按钮都不解释为什么灰（S1 严重）

**问题**
禁用状态的按钮旁边没有任何说明，用户不知道是坏了、还是自己漏了什么。

**证据**（三个位置，同一个病）：

| 位置 | 代码 | 现象 |
| --- | --- | --- |
| 内容评审 | `ReviewsPage.tsx:234`<br>`disabled={!selectedRoles.size}` | 角色未勾选 → 按钮灰，页面零提示 |
| 文章排版 | `LayoutsPage.tsx:170`<br>`disabled={busy \|\| !articleId}` | 未选文章 → 按钮灰，空态却写「选择平台后点击」 |
| 框架生成 | `FrameworksPage.tsx:142`<br>`disabled={stream.active \|\| !models.length}` | 未配模型 → 按钮灰，无说明（配图页有说明，排版/框架/文章都没有） |

**用户感受**
「按钮是灰的，我点不动，但页面没告诉我缺什么。是我哪里做错了吗？还是它坏了？」

我会去乱点其他页面寻找原因，浪费时间。

**影响**
不阻断任务（用户最终会误打误撞勾上），但**每个环节都要卡一下**，且怀疑是自己操作错误 → 降低对产品的信任。

**等级 S1** — 任务能完成，但三个核心环节都有障碍

**修改建议**
1. **禁用时在按钮旁给出原因**，例如：
   `开始评审`（灰） + 文字「请先勾选至少一个评审角色」
2. **空态说明与真实前置条件对齐**：排版页从「选择平台后点击」改为「先在上方选择文章，再点击生成排版稿」
3. 更好的做法是**先让按钮可点**，点了再 toast 提示——但这不如前者。我建议用 1+2，成本低、见效快。

---

### 问题二：账号定位 9 个空白字段，新手不知道填哪几个（S1 严重）

**问题**
9 个字段全部空白，完整度 11%，但没有任何「最少填哪几个」或「哪些最重要」的指引。

**证据**
`artifacts/release-acceptance/03-账号已建.png`：账号名称、简介、领域、目标受众、写作风格、IP 人设、差异性定位、价值主张、选题方向——9 个全空。代码里这些字段**没有 required 标记**（`grep required` 无结果），所以用户不知道哪些是必须的。

而 `completeness` 百分比只是数字，没告诉用户「达到多少才算够」。

**用户感受**
「我跳过 AI 追问/manual填字段，现在面对 9 个框。填哪个？不填会怎样？11% 是不是很差？」

真实用户很可能在这里直接放弃，转而去网上搜「怎么写公众号」。

**影响**
这是**漏斗最前端**。账号定位填不完，后面选题生成、框架生成全部连带受阻（S1）。

**等级 S1**

**修改建议**
1. 给字段分组并标出优先级：
   `必填（3）`：账号名称、目标受众、写作风格
   `建议补充（6）`：其余
2. 完整度旁边加一句状态说明：
   `< 40%` 「还能用，但成稿会更generic」/ `40-80%` 「基本够用」/ `> 80%` 「很好」
3. 顶部给一句话引导：「先填这 3 个就能开始写，其余可以之后补」

---

### 问题三：模型标识字段缺少示例，新手容易填错导致连不上（S2 明显摩擦）

**问题**
「模型标识」是必填项，但字段下方没有 placeholder、没有示例、没有说明它是外部服务的模型名。

**证据**
`ProvidersPage.tsx:647` 附近：`<span>模型标识</span>` 之后直接是 input，**无 placeholder、无 help 文本**。

**用户感受**
「这是什么意思？要填什么？`gpt-4o`？`deepseek-chat`？填错了会怎样？」

**影响**
填错要等「测试连接」失败才发现，来回试错。属于摩擦但不阻断（有厂商标签兜底）。

**等级 S2** — 不阻断任务，但明显降低首次成功率

**修改建议**
加 placeholder + 一行帮助文案：
```
placeholder="如 gpt-4o / deepseek-chat / doubao-pro"
帮助：本服务商的模型名称，填错会导致测试连接失败
```

## 7. 用户脑力负担分析

### 现在是用户在替 AI 想（应该 AI 替用户想）

| 用户被迫做的判断 | 本该谁做 | 现状 |
| --- | --- | --- |
| 「我该填哪几个字段」 | AI | ❌ 9 个等权空白，无优先级 |
| 「为什么按钮点不动」 | AI | ❌ 无任何提示 |
| 「模型标识填什么」 | AI | ⚠️ 靠厂商标签部分兜底 |
| 「我完成多少才算够」 | AI | ⚠️ 只有一个 11% 数字 |

### 已经做得好的（AI 在替用户想）

- 首页「第一步：连接一个文本模型」——直接告诉用户第一步
- 三处阻塞提示都带「去哪弄」的按钮
- 流水线步骤条让用户始终知道自己在哪、下一步是谁
- 侧边栏 9 页全部有「下一步」引导（这是本轮导航统一带来的直接收益）

**结论**：**「流程引导」做得很到位，「内容引导」有明显缺口。**
用户能被带着走完流程，但进到需要填内容的页面就没人带他了。

## 10. 一定要先改的一件事

### **给所有禁用按钮加上原因提示**

**为什么是这个**：这不是三个独立的小 bug，是**一个统一的设计习惯缺失**。修它只需建立一个模式（禁用时附原因），就能一次性消除 3 个 S1/S2，而不是逐个打补丁。

具体最小改动（3 处，各 1–2 行）：

```tsx
// ReviewsPage.tsx
<button className="button primary"
  disabled={!selectedRoles.size || retrying}
  title={!selectedRoles.size ? '请先勾选至少一个评审角色' : undefined}>
  开始评审
</button>
// 更好：在按钮上方显示一行小字
{!selectedRoles.size && <p className="form-hint">勾选至少一个角色后可开始</p>}
```

```tsx
// LayoutsPage.tsx 空态文案
- description="选择平台后点击「生成排版稿」。"
+ description="先在上方选择文章，再点击「生成排版稿」。"
```

```tsx
// ProvidersPage.tsx 模型标识字段
- <span>模型标识</span>
+ <span>模型标识</span>
```

### 问题 1：实际改了 10 处，比报告预估的 3 处多

报告只点了内容评审、文章排版、内容框架三处。**实施时做了全量排查**，发现同类问题共 6 个页面 10 处：

| 页面 | 处理 |
| --- | --- |
| 内容评审 | 按钮下加「勾选至少一个评审角色后即可开始」+ 角色标题加「必选」 |
| 文章排版 | 加「请先在上方选择要排版的文章」 |
| 内容框架 | 加「还没有可用的文本模型，请先到 模型网关 配置」+ 模板/主题两个前置提示 |
| 选题生成 | 加模型缺失引导 |
| 智能配图 | 加「请先选择文章」/「请先选择方案模型」两条 |
| 文章创作 | 加模型缺失引导 |

统一模式：按钮旁`.form-hint` 就近说明 + `title` 属性（悬停可见）。**框架/选题页的提示里直接嵌了「模型网关」跳转按钮**，用户不必侧边栏找。

### 问题 2：账号定位字段优先级

- 顶部提示条：「先填 **账号名称、目标受众、写作风格** 这 3 个就能开始写，其余可以之后补」
- 三个核心字段标「必填」（锁定态显示「关键」——查看时用户同样需要知道重点）
- 字段内placeholder 分两档：核心字段「这个字段会直接影响成稿，优先填写」，其余「可稍后补充」
