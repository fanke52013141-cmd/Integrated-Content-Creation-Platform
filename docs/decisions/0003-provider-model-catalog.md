# ADR-0003：一个供应商连接维护多个模型

- 状态：已接受
- 日期：2026-07-28

## 决策

`Provider` 只保存协议、Base URL、加密密钥和能力；实际模型存入独立的
`provider_models` 目录。一个连接可以配置多个模型，每个模型包含：

- API 模型 ID；
- 用户可读别名；
- 上下文和输出上限；
- 可用推理档位；
- 启用状态；
- 是否为该连接的默认模型。

每个连接必须且只能有一个已启用的默认模型。业务调用同时传
`provider_id + model_id`，网关拒绝调用未登记或已停用的模型。

## 兼容策略

旧版供应商的 `default_model` 会在数据库初始化时自动迁移为模型目录中的第一条默认模型，不要求用户重新配置 Key。

## 原因

Base URL 和 Key 属于连接，模型属于连接下的资源。拆分后可以避免为每个模型重复保存相同密钥，也能支持账号定位的“换模型重新生成”。
