# ADR 0009：固定版式组件配置与无副作用样稿预览

状态：已决定（2026-10-22）

## 背景

账号版式首批仅能调整字号、间距和颜色。用户需要制定一套较完整的公众号规范，并在启用前检查标题、正文、图片说明、引用、列表、表格、代码和文末内容。仅预览某一篇文章不一定覆盖这些组件；为预览而创建正式排版稿也会污染交付历史。

## 决策

1. 版式仍以 `LayoutStyleConfig` 结构化 JSON 为唯一配置源；CSS 由固定主题和组件变体编译生成。字体和样式变体使用枚举，尺寸、颜色、品牌文本由主进程 IPC 校验。
2. 增加标题层级、字体、引用、图片圆角与图注、段首缩进、正文是否重复显示标题等组件规则。
3. 账号版式可以包含固定开篇说明和文末署名。这些文字是版式组件，会进入输出 HTML 和纯文本，不改写文章原文；只保存到对应账号和平台的版式版本。
4. 排版页提供覆盖常见 Markdown 组件的标准样稿。预览由主进程确定性渲染，但不写入 `article_layouts`；编辑参数时自动刷新样稿。
5. Markdown 图片以块状图片组件输出，非空 alt 文本同时作为图注；预览占位图使用内嵌像素，不访问外部示例图站点。
6. 从本次变更起，正式排版稿写入渲染器版本 `mly-layout-v4`（整合线上组件、合规处理与账号版式后的版本）。已经保存的旧 HTML 不重新渲染。

## 后果

- 账号版式可覆盖更完整的文字和图片阅读规则，预览不产生正式排版历史。
- 可将内置主题与结构化参数导出为 JSON 版式包，也可导入到编辑区预览；导入不会立即覆盖账号绑定，保存默认版式时才创建新版本。版式包不包含账号凭证和本机图片路径。
- 固定开篇/文末文字对旧版本保持快照效果；用户修改后需保存新账号版式版本，后续新稿才应用。
- 当前版式包只覆盖内置主题和结构化参数，不包含 CSS 导入导出、品牌图像资产或每个组件的任意高级 CSS；这些继续按实施方案后续完成。
- 微信真实客户端对 CSS 的处理仍需用固定样稿验收。
