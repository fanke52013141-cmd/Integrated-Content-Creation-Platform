# 全量优化方案：待办盘点与分期计划（2026-11-09）

> 输入：三路并行盘点（PRD × 实现差距、代码与文档遗留标记、工程质量审查）+ 关键代码核实。
> 基线：491 个测试全绿、strict TS（3 万行仅 6 处 any）、安全配置无高危项、14 页面 + 9 个 PRD 模块。
> 结论：写文章 / 账号定位 / 热点 / 素材四模块实现度高；核心缺口集中在「排版 AI 轻编排」「选题池化」两块 P0，以及一批 P1 功能点、发布链路天花板（freepublish）和工程债（database.ts 巨石 + 无版本化迁移 + 无 lint 门禁）。

## 一、总体原则与批次总览

- 每批次独立交付：可单独验收、可回滚、附 `docs/交付说明-XXX-日期.md` 交接文档，commit 沿用现行规范（`type(scope): 中文描述——要点`）。
- 功能批次与工程债批次分开做，避免大 diff 混入功能变更。
- 凡「实现与 PRD 口径相反」的项，先确认产品意图再动代码（见「十一、开放决策」）。
- 涉及外发动作（公众号「发表」）必须显式 HITL 确认。

| 批次 | 内容 | 估时 | 风险 | 前置 |
|---|---|---|---|---|
| 1 | 口径对齐与快速修正 | 1~1.5 天 | 低 | 无 |
| 2 | **排版 AI 轻编排**（P0-1） | 3~4 天 | 中 | 无（基础设施已就绪） |
| 3 | **选题池化与单卡重试**（P0-2） | 2 天 | 低 | 无 |
| 4 | P1 功能集合（评审/框架/素材/热点/配图） | 4~5 天 | 低~中 | 无 |
| 5 | 工程债专项（database 拆分/迁移/分页/lint/CI） | 3~4 天 | 中 | 建议在批次 6 前 |
| 6 | 公众号「发表 freepublish」链路 | 2~3 天 + 真机验收 | 中 | 真实认证账号凭证 |
| 7 | 体验与维护性细节（暗色兜底等） | 1.5~2 天 | 低 | 无 |

合计约 17~21 人日。批次 2/3 可并行；批次 7 的条目相互独立，可拆散插空做。

## 三、批次 2：排版 AI 轻编排（P0-1，3~4 天）

> PRD-排版AI §4.1 的核心 AI 职责整体未开发：`<排版方案>`（配图插入点 + 推荐模板 + 导读 + 结尾互动语）。现状 `layouts:create`（`ipc.ts:1013-1017`）为纯确定性渲染，`prompt-registry.ts` 无 layout 角色。
> 有利条件：`extractBlock` 抗 CoT 截取（`gateway/extract-block.ts`）、VisualStudio 的 blockIndex 段落锚点、`layout-themes.ts` 主题体系、`layouts:render-check` 校验、golden 测试全部就绪，本批次主要是「串新链路」而非「造地基」。

### 3.1 提示词角色

新增 `layout.plan` 进入 `BUILTIN_PROMPTS`（seed v1），模板要点：

```
你是公众号排版编辑。根据输入输出一个 <排版方案> XML 块，内部用「键：值」纯文本约定，不使用 JSON。
配图插入点：每项一行「图片：<path> ｜ 位置：第N段之后/文首/结尾之前 ｜ 说明：<一句话>」；
  位置必须基于 <成稿> 当前段落重新语义推导，不机械沿用旧锚点；成稿已有图片的位置不重复推荐。
推荐模板：从 <可用模板> 中选一个 themeId ｜ 理由：<一句话>；用户已选模板时输出「沿用：<themeId>」。
封面位：填封面资产 path，无封面则输出「无」。
导读：一句钩子文案，不触碰正文。结尾互动语：一句引导评论的文案。
不得虚构成稿与素材之外的事实；图片 path 必须原样引用输入中的 path。
```

输入组装（XML 包裹纯文本，沿用全局防注入约定）：`<成稿>`（必填）、`<配图资产>`（可选，path + 用途 + 比例，来自 VisualStudio 采纳结果或快速配图包）、`<账号定位>`（可选，模板推荐参考）、`<可用模板>`（themeId + 名称列表）、`<用户已选模板>`（可选）。
网关调用：`extractBlock: { tag: '排版方案', occurrence: 'last' }`；模型选择沿用现行「每环节独立选模型」模式，默认取全局默认 LLM（对齐 PRD「轻任务保持简单」）。

### 3.2 解析器（新文件 `src/main/services/layout-plan-parser.ts`）

- 行导向宽松解析：`配图插入点 / 推荐模板 / 封面位 / 导读 / 结尾互动语` 五段全可选，段内行用 `｜` 或全角空格切分。
- 产出结构（入 `shared/contracts.ts`）：`LayoutPlan { insertions: Array<{ assetPath, anchor: 'after-paragraph-N' | 'leading' | 'before-ending', note }>, recommendedThemeId?, recommendedReason?, coverAssetPath?, leadIn?, closing? }`。
- 锚点校验：`N` 与成稿实际顶层块数比对，越界则收敛到最近合法值并标记 `warnings: string[]`；`assetPath` 必须存在于输入资产列表，未知 path 丢弃并记 warning。
- 解析失败不阻断：空 plan 等价于「纯文字排版」现状路径，`extractionMatched=false` 时 UI 提示「AI 方案解析未命中，已保留人工模式」。

### 3.3 渲染落位（`article-layout-service.ts` 扩展）

- `layouts:create` 入参增加可选 `plan?: LayoutPlan`：渲染前在 Markdown token 层按锚点插入正文图（`![](path)`），`leadIn` 以引用块插入文首、`closing` 追加文末——**只改渲染输入，不改文章源稿**。
- 排版稿快照（layout draft）保存 plan 与渲染器版本，保证可复现与回滚。
- `layouts:render-check` 增加插入项校验：插入图片是否出现在产物 HTML、锚点是否合法。

### 3.4 UI（LayoutsPage 排版入口）

- 生成面板新增「AI 排版方案」开关（默认开）+ 独立「生成排版方案」按钮（可单独重跑，不连带重渲染）。
- 方案卡片：插入点列表（行内编辑锚点下拉：第 N 段之后 / 文首 / 结尾之前）、推荐模板（可切换，附 AI 理由）、导读与互动语 textarea、封面位选择。
- HITL 分两步：先「确认方案」再「生成排版稿」；本轮不做预览内拖拽（见开放决策 6），锚点下拉已是等价交互。

### 3.5 测试与验收

- 单测：`tests/layout-plan-parser.test.ts`（正常 / 字段缺失 / 锚点越界 / 未知 path / extractBlock 未命中兜底）；`tests/layout-e2e.test.ts` 补「带 plan 渲染」链路；golden 用例补一张带插入点快照（重生成需 `MLY_REGEN_GOLDEN=1` + 视觉说明）。
- 验收标准：20 篇真实样本 extractBlock matched ≥ 98%（对齐 PRD §8 指标）；插入图与导读/互动语出现在最终 HTML；无 plan 路径行为与现状完全一致（回归零差异）。

## 四、批次 3：选题池化与单卡重试（P0-2，2 天）

> PRD-选题AI §4.4 的 P0 机制：账号池 + 关键词池「轮询分配」+ 可选穷举模式。现状 N 次调用全部同账号同关键词（`ipc.ts:679-690` 单数 `accountId`/`seedKeyword`；`topic-generator.ts:50-67`）。
> 有利条件：数据层 `Topic.accountIds` 已是数组（`topic-generator.ts:45` 按 includes 过滤），DB 无需迁移。

### 4.1 契约与服务改造

- `GenerateTopicsInput`（`contracts.ts:599`）：`accountId → accountIds: string[]`（1~10 个，均须锁定）、`seedKeyword → seedKeywords: string[]`（1~10 个）；新增 `mode: 'round-robin' | 'exhaustive'`（默认轮询）。IPC schema、preload、mock-bridge 同步。
- 分配算法：
  - 轮询：第 i 次调用取 `accountIds[i % A]` + `seedKeywords[i % K]`；
  - 穷举：任务数 = A × K × count，笛卡尔积展开；上限保护：产物数 > 30 时 UI 红字预警需二次确认。
- 失败隔离沿用 `Promise.allSettled`；`historyTitles` 按每次任务对应账号过滤。
- 生成结果卡片标注来源账号与关键词（来源徽标机制已有）。

### 4.2 单卡重试（选题 + 框架一并补齐）

- 对齐文章模块已有能力（`articles:retry-request`/`recover-result`）：新增 `topics:retry-one` 与 `frameworks:retry-one`——入参为失败项的原始输入快照（账号/关键词/热点组/schema 或模板/素材），单卡「重试」按钮直接重跑该条，成功后原位替换。
- 失败卡片从「整批补齐提示」升级为单卡可操作（`TopicsPage.tsx:193`、FrameworksPage 对应处）。

### 4.3 UI（TopicsPage 生成面板）

- 账号改多选 chips（可选「不使用账号定位」= 通用创作池）；关键词改多行输入（每行一个）或回车添加 tag；模式开关默认轮询、穷举带产物数实时预估。

### 4.4 测试与验收

- `tests/topic-generator.test.ts` 补：轮询分配矩阵正确性、穷举展开与上限、混合失败隔离、按账号去重历史；IPC 单测补新 schema 校验。
- 验收：3 账号 × 2 关键词 × count 2（轮询 6 条产物分配正确）；单卡重试可用；老入参（单账号单关键词）路径行为不变。
