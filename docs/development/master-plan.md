# 集成内容创作平台：开发总纲与落地方案

> 版本：v1.0，2026-11-26
> 状态：阶段 0 真实 POC 已通过，进入持续开发。
> 核心原则：**先保证微信端确定可用，再逐步增加视觉复杂度。**

## 1. 主要目的（North Star）

**让创作者在本平台完成写作、编辑和品牌化排版后，系统能够自动产出微信公众号可正常阅读的文章，并同步为可核验的草稿；除首次账号与品牌配置外，日常创作不再要求复制粘贴、手工传图、逐篇确认或处理兼容问题。**

这里把“正常显示”定义为可测量结果，而不是一句宣传语：

1. 正文非空白内容不丢失。
2. 图片、封面、表格、代码、列表、引用、链接尾注等声明支持的内容在微信中可用、可读。
3. 支持矩阵内无 P0 兼容问题；不支持的效果在同步前自动降级或明确阻断。
4. 同步后可读回、可比较、可追溯，失败可自动恢复且不产生重复草稿或重复素材。
5. 每套主题都通过相同的真实浏览器、官方 checker、自定义 lint 和真实公众号回归。

**边界**：不承诺任何未声明的 CSS、任意 SVG 动效或未来微信版本都“绝对无问题”。承诺的是：系统不会把未经验证的效果静默交付给用户。

## 2. 目标使用方式

### 一次性配置

1. 用户连接专用公众号或第三方授权账号。
2. 用户设置品牌色、Logo、摘要、默认封面、主题和自动同步策略。
3. 系统验证账号权限、出口 IP、素材接口与测试草稿读回。
4. 用户开启“自动同步到草稿”。

### 后续日常创作

```text
写作/粘贴/导入
    ↓
选择品牌主题、实时查看微信效果
    ↓（系统后台自动执行，无需逐篇操作）
文档规范化 → 主题编译 → 安全检查 → 图片处理
    ↓
创建/更新公众号草稿 → 读回 → 差异报告
    ↓
在公众号后台查看或继续运营
```

- 同步以**草稿**为默认终点，不把发布或群发混入日常保存。
- 同一文章重复保存应更新原任务/草稿，不能反复新增。
- 失败时只在需要用户处理的事项上通知，例如凭证失效、账号权限不足或内容必须改写；普通网络重试和素材去重由系统处理。

## 3. 四层产品架构

### 3.1 编辑体验层

- 以 `doocs/md` 为上游底座，跟随安全与兼容修复。
- 提供 Markdown 编辑、实时预览、自动保存、版本历史、主题选择、图片库和文章元数据。
- 后续增加面向非技术用户的块级可视编辑，但 Markdown 与可视编辑必须共享同一文档模型，不能产生两份内容。
- 微信专用 HTML 只是输出，源文档、主题版本、素材与渲染版本才是主数据。

### 3.2 确定性主题层

- 主题由 `Design Tokens + Components + Recipes` 组成，不允许 AI 或页面任意拼接 HTML/CSS。
- 主题编译器输出确定的微信 CSS，再经 doocs `processClipboardContent()` 内联和结构修复。
- 首发原创主题：
  - **Aurora Tech / 科技蓝**：深色代码、蓝色层级、信息卡片和技术文档节奏。
  - **Editorial Red / 编辑红**：红色标题锚点、杂志式留白、引用与评论文章层次。
  - **Emerald Notes / 翡翠笔记**：绿色标签、柔和底色、知识点和教程组件。
- 主题必须版本化；旧文章永远可以按旧版本重现，不随新主题静默变化。

### 3.3 微信兼容质量层

采用多道独立质量门：

1. 输入 HTML、URL、CSS、文件类型安全清洗。
2. 自定义兼容 lint，补足危险属性、`span[leaf]`、`section[nodeleaf]`、图片元数据等规则。
3. doocs 的微信 DOM/SVG 后处理。
4. 官方 `verify-article-structure` 的真实 Chromium 检查。
5. MP JSAPI 或服务端草稿读回，比较可见文本、非空白文本和有效图片地址。
6. 真实移动端的发布前抽查（后续阶段）。

任何一层发现 P0 问题都不得自动创建/更新草稿。

### 3.4 自动交付层

以可恢复状态机执行：

```text
RECEIVED
→ RENDERED
→ INSPECTED
→ ASSETS_UPLOADED
→ DRAFT_UPSERTED
→ READBACK_VERIFIED
→ COMPLETED
```

- 幂等键：`accountId + documentId + documentRevision + themeId + themeVersion + rendererVersion`。
- 每一步持久化结果；进程失败后从最后成功步骤继续。
- 相同素材按内容哈希去重，相同任务重复执行零重复网络副作用。
- 支持超时、有限重试、错误分类、人工阻断原因和结构化报告。
- 发布/群发不属于本状态机，后续若增加必须独立授权与审计。

## 4. 丰富前端样式的设计边界

### 可以优先使用

- 品牌色、灰阶、纯色与适度的 rgba 背景。
- 字号尺度、行高、字距、段距、留白、分隔线。
- 左竖条、短标签、圆角卡片、纯色标题带、引用块、提示块。
- 受控 `flex`、百分比/`max-width` 响应式布局。
- 表头底色、单元格间距、横向滚动代码与宽表格。
- 原创 SVG 图形的安全子集；必要时栅格化并提供静态图。

### 默认禁止或必须降级

- 脚本、任意 iframe、外链 CSS/字体、事件属性、`javascript:` URL。
- `grid`、关键定位、`float`、关键动画和依赖 CSS 变量才能成立的最终效果。
- 以纯文本图片代替可编辑正文；必要图表才允许图片化并保留替代文本。
- 未经验证的 SVG 交互、弹窗、音频、小程序特殊效果。
- 依赖伪元素才能显示的关键内容；装饰性伪元素必须可以安全消失。
- 文字区域的复杂渐变、低对比度配色和不可读透明图。

**视觉策略**：用排版尺度、色彩层级、边框、卡片和组件组合形成设计感，而不是把网页特效直接塞入公众号。

## 5. 兼容与降级策略摘要

| 内容/效果 | 默认策略 | 失败时 |
|---|---|---|
| 标题、段落、列表、引用、强调 | 原生支持并内联主题样式 | 阻断并定位节点 |
| 代码块 | 高亮、横向滚动、保留文本 | 使用 `pre/code` 安全结构；不可读则阻断 |
| 宽表格 | 简化结构、响应式或横向滚动 | 不能安全阅读则拆表或阻断 |
| 普通外链 | 转底部参考文献 | 保留可见标题和 URL |
| 正文 JPG/PNG | 校验真实 MIME、压缩、微信上传、`data-w` | 不创建草稿并返回具体图片 |
| GIF/超大图/透明图 | 单独能力检查，不假装支持 | 经确认的降级或阻断 |
| KaTeX/MathJax | 浏览器真实渲染、安全 SVG/图片 | 静态降级，不丢失公式文本 |
| Mermaid/PlantUML | 浏览器完成图形布局后转换 | 静态图或明确失败，不保留加载占位 |
| 任意 SVG 互动 | 默认不开放 | 仅使用单独认证组件并提供静态降级 |
| 自定义字体 | 默认微信字体栈 | 不引入外链字体 |
| 未识别 CSS/标签 | 清除安全冗余或阻断 | 记录规则与源节点，不静默丢失正文 |

## 6. 自动化工程方案

### 6.1 保存触发

- 编辑内容停止变化后进行防抖处理。
- 先生成轻量预览；官方 Puppeteer 检查放到导出队列，避免每次按键都启动浏览器。
- 同一文档只允许一个活动交付任务，新任务替代未开始的旧任务，正在执行的步骤必须安全结束或恢复。

### 6.2 素材自动化

- 本地/远程素材先进入统一资产库，记录哈希、格式、大小、尺寸、授权信息。
- 相同“账号 + 图片哈希 + 处理参数”直接复用已上传 URL。
- 正文图和封面分开处理；外部图片不直接进入草稿。
- 上传失败按错误类型自动重试；永久错误返回素材级 blocker。

### 6.3 草稿与读回自动化

- 首次创建后保存 `media_id`，后续优先更新而不是新增。
- 读回比较正文与图片，并记录微信实际改写。
- 任务完成保存可复现快照：输入、主题、渲染器、输出、校验、素材、草稿与差异。
- 真实账号 nightly 回归使用专用测试文章，不依赖人工点击。

### 6.4 凭证与安全

- AppSecret/access_token 只在服务端密钥系统；浏览器不保存长期 Secret。
- 多租户优先微信第三方平台授权；内部单账号可使用本地加密配置。
- 日志只保留错误码、rid、任务 id 和脱敏素材信息。
- 远程图片抓取需要 SSRF、重定向、MIME、像素、大小与超时防护。

## 7. 里程碑与验收

### M0：真实 POC（已完成）

- doocs 最终渲染、官方 checker、MP JSAPI 写入与读回。
- 非空白正文一致，微信托管图片真实可见。
- 本地相对图片失败已记录，未冒充素材 API 成功。

### M1：开发地基（当前）

- 原创主题编译器与三套主题。
- 兼容矩阵与自定义质量包。
- 幂等、可恢复的自动交付状态机。
- 统一开发脚本、测试、SBOM 和迭代看板。

**退出标准**：所有包可独立测试；同一文章在三套主题下生成预览并通过本地质量门；重复执行任务没有重复副作用。

### M2：编辑到草稿的一体化 MVP

- 编辑、主题选择、元数据、封面、自动保存和预览。
- 一次账号配置后自动创建/更新草稿和读回报告。
- 失败任务自动恢复，用户不需复制、传图或逐篇确认。

**退出标准**：从新建文章开始，无手工中间步骤即可在公众号后台看到正确草稿；重复保存只更新同一文章。

### M3：生产可用与完整内容矩阵

- 账号授权、凭证轮换、多账号、任务监控和通知。
- MathJax、Mermaid、DOCX 导入、更多图片场景与错误注入。
- 真机/Dark Mode 回归与发布前性能 SLO。

### M4：品牌与团队能力

- 品牌工具包、企业私有主题、组件配方、评论/审核、权限和审计。
- 参数化高级组件与少量经过专项验证的 SVG 互动模板。

### M5：多平台与数据闭环

- 平台适配器、跨平台素材处理、渠道回执与对账。
- 阅读/互动数据反哺标题、主题和内容版本。

## 8. 持续质量机制

### 每次代码变更

- 单元测试、类型检查、主题快照、危险输入测试。
- doocs 构建、主题真实 Chromium 渲染、自定义 lint。
- 有 HTML 变化时运行官方 checker。

### 每日自动回归

- 使用专用测试公众号执行创建/更新/读回，不发布。
- 检查重复素材、重复草稿、网络重试、凭证过期和恢复。
- 输出趋势：非空白文本、有效图片、P0 数、平均耗时、失败原因。

### 发布前

- 全主题 × 全语法 × 多尺寸 × Dark Mode 矩阵。
- 至少一次真实公众号端到端回归。
- 许可证/SBOM/资产授权检查。

## 9. 当前迭代顺序

1. `packages/wechat-theme`：三套原创主题与编译器。
2. `packages/wechat-quality`：兼容矩阵与自定义 lint。
3. `packages/wechat-publisher`：幂等交付状态机。
4. 主题接入 doocs，生成三主题真实预览与官方检查。
5. 编辑界面整合主题选择、元数据与任务状态。
6. 接入真实账号自动草稿更新与 nightly 回归。
7. 再扩展复杂组件、协作和多平台。

**不得颠倒顺序**：不在质量门和素材自动化完成前，先建设大型模板市场或自由 SVG 编辑器。
