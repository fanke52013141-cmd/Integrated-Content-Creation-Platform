# Handoff：账号固定版式、配图工作台与文章页优化

交接日期：2026-10-22（Asia/Shanghai）。

仓库：`fanke52013141-cmd/Integrated-Content-Creation-Platform`，交付分支：`master`。

本批改动基于 `7c1d740`（`feat(visuals): 完成内容配图工作台与风格管理`）。交付提交同时包含本文和代码，准确提交号可通过 `git log -1 -- docs/HANDOFF-2026-10-22.md` 查看。本文承接本轮开发，历史 `HANDOFF-UI-REDESIGN.md` 只作为早期记录。

## 1. 用户目标与交付范围

1. 每个公众号维护一套固定版式，后续文章自动套用，旧排版稿保留生成时的样式。
2. 按内容规划封面、顶部图和正文图，选择风格后生成提示词，再使用参考图生成候选图。
3. 生图任务、方案草稿能够跨页面和重启恢复，修改单张配图后能增量更新。
4. 修复文章工作台标题被按钮挤窄、搜索与筛选错位、草稿徽标拉满整行的问题。

上述功能已落入源码并完成生产构建。真实付费供应商的画面质量、真实公众号粘贴／草稿箱及手机显示仍需专项验收；最终代码的完整自动化回归状态见第 6 节。

## 2. 功能入口与当前行为

### 2.1 账号固定版式

- 入口：**账号定位 → 公众号版式**。无关联文章时也能编辑，用标准组件样稿预览。
- 结构化参数包含正文、标题、段落、强调色和品牌文字等；支持配置包导入／导出、样稿预览、历史版本。
- 保存草稿与启用版式分开。保存草稿不改变账号默认版式；启用时新增不可变版本并切换默认绑定。
- 草稿 revision 和当前绑定一起校验，旧窗口保存或启用发生冲突时保留用户编辑。
- 新排版优先读取文章所属账号的默认版式；支持单篇覆盖。账号没有配置时沿用内置主题。
- 正式排版稿冻结最终 HTML、配置快照、版式版本和渲染器版本。当前渲染器标识为 `mly-layout-v4`。
- 文章实时预览、配图应用预览与正式排版共用渲染器，并传入文章 ID 解析账号版式。
- 保留线上已有的微信交付预检、上传与复制、结果未知处理和重试流程。

账号画像的版式绑定与公众号 AppID 授权不同。发布凭证仍沿用现有通道，本批没有实现多个公众号授权通道管理。

### 2.2 内容配图工作台

入口：**智能配图 → 内容配图工作台**。界面按“内容方案 → 风格 → 图片 → 应用”四阶段组织。

| 能力 | 当前行为 |
| --- | --- |
| 内容规划 | 独立选择封面、顶部图及正文图，生成配图理由、位置、比例和主体 |
| 风格 | 账号默认风格、整篇风格、单图覆盖、文字描述和主参考图；风格按版本引用 |
| 提示词 | 人工修改和锁定；改动一张图只让该图提示词失效 |
| 生图 | 单图和批量进入同一个主进程队列；支持质量、分辨率和参考图模式 |
| 候选图 | 保存生成参数签名；区分可用、需要更新、缺少历史参数记录 |
| 增量生成 | 批量只提交缺图或旧图位置；提示词过期时先要求更新 |
| 旧图采用 | 明确确认后可沿用；再次修改内容或风格会让该确认失效 |
| 自动草稿 | 编辑后防抖写入 SQLite，会话缓存兜底；显式保存校验草稿与正式方案 revision |
| 草稿冲突 | 对照旧草稿与新方案，允许载入检查；保留递增 revision 的空记录避免旧客户端误写 |
| 位置修复 | 原段落找不到时最多提供两个相似位置，显示原文与候选，确认后才更新位置 |
| 应用 | 整篇预览后写为文章新版本，封面独立绑定发布表单，保留原有撤销规则 |
| 费用 | 展示已记录费用、估算标记和费用未知数量；真实账单以供应商返回为准 |

普通生图传递分辨率字段；参考图编辑将 1K／2K／4K 转为对应像素尺寸。供应商不支持时返回错误，界面不静默丢弃参考图或降低质量。

### 2.3 任务恢复与重复提交保护

- 队列保存在 SQLite，主进程串行执行，切换页面不会停止任务。
- 未提交的排队任务在启动后继续执行。
- 已取得供应商任务标识的任务优先查询原任务并恢复资产。
- 提交中断且没有远端标识时标记“结果待核对”，需要人工确认后才允许再次提交。
- “再查一次”只续查已有标识，不发起新的付费生图请求。
- 暂停、继续、明确失败重试、结果核对与全局任务台账联动。
- 风格样图另存任务及创建参数，支持续查与载入恢复后的风格参数。

### 2.4 文章工作台样式

- 标题和说明保留完整宽度，操作按钮另起一行并按空间换行，移除重复的按钮组包装。
- 文章栏调整为 260px；标题、搜索框和两组筛选器统一对齐，分段按钮等宽。
- “草稿／已锁定”按文字宽度显示，文章条目统一留白、字号和分隔线。
- 长列表在侧栏内滚动，分页操作在滚动区外；翻页后回到列表顶部。
- 搜索防抖只在关键词确实变化时重置页码，修复初次进入后翻页可能回到第一页的问题。
- 读取期间保留旧列表并禁用条目和分页，显示读取状态，避免控件因列表清空而跳动。
- 根据实际内容区宽度切换布局，兼容侧栏和缩放；窄内容区先将辅助栏移到下方，再改为列表／正文上下排列。
- 补充专注写作的栅格覆盖，避免隐藏辅助栏后仍保留空列。

### 2.5 其他随批改动

- 热点源排序补充上移／下移按钮，保留拖拽；拖拽数据显式写入 `dataTransfer`。
- 微信正文图缓存按 AppID 与当前文件内容摘要查询，避免同名文件更新后复用旧图；封面上传仍使用独立路径。
- 旧桌面回归脚本同步新建弹窗、工作栏和页签语义；新增账号版式脚本并加入全量 smoke 列表。
- 未新增第三方运行依赖。`package.json` 增加账号版式回归入口。

## 7. 接手后的执行顺序

1. 阅读本文及 ADR 0008—0012；从账号版式、配图工作台、文章页三个入口查看已有行为。
2. 优先完成最终自动化回归，保留失败证据；单元测试与 Electron smoke 分开执行。
3. 检查队列恢复的边界：远端任务标为完成、但对应本地资产缺失时，当前 `reconcile()` 未显式转入终态，需要补充处理，避免任务长期处于 recovering。
4. 用真实供应商验收文字风格与图片参考模式、实际输出尺寸、费用返回和风格一致性。
5. 选定一个公众号的正式版式与参考风格，分别验收复制粘贴、草稿 API 及手机显示。

供获授权的后续验证使用：

```powershell
npm.cmd install
npm.cmd run build
npm.cmd test -- --maxWorkers=4
node scripts/smoke-account-layouts.mjs
node scripts/smoke-visual-studio.mjs
node scripts/smoke-articles.mjs
node scripts/smoke-hotspots.mjs
node scripts/smoke-workspace.mjs
# 独立完成以上项目后，再运行完整桌面回归
node scripts/run-all-smokes.mjs
```

脚本默认使用临时数据目录和本地模拟供应商。真实调用应使用现有供应商配置与项目认可的环境变量方式，密钥不得写入交接文档或提交。

## 10. 同步与回退

本批以单个 Git 提交同步代码、设计记录、本文和界面证据，提交说明列出主要功能与剩余验收项。提交后使用 `git rev-parse HEAD` 与 `git ls-remote origin refs/heads/master` 核对远端版本。

需要回退时，在共享分支使用普通 revert 提交保留历史。涉及已升级数据库时先备份当前数据，恢复与目标代码匹配的数据备份后再使用旧版本；不能仅靠回退源码保证数据回退。
