# 心流 · 排版引擎重做与素材链路优化方案

> 日期：2026-08-29 · 依据：五段式产品设计走查 + 开源调研（详见对话记录）
> 范围四个批次：A 排版引擎重做（核心）· B 文件上传素材 · C 自动衔接三件套 · D 可选增强
> 原则：不改变 HITL 流程与既有数据结构语义；所有新增能力可独立回滚。

---

## 批次 A：排版引擎重做（核心，约 1.5~2 天）

### A0 问题确诊
现引擎（`src/main/services/article-layout-service.ts`）为手写逐行解析：
- 仅支持标题/列表/引用/段落，**加粗、斜体、链接、表格、代码块、图片全部不识别**（`**加粗**` 原样输出）；
- 仅一套硬编码绿色样式，无主题概念；
- 产出的 HTML 恰好全内联（歪打正着兼容微信），但表现力为零。

### A1 技术方案（业界标准做法，doocs/md 同款链路）
微信后台过滤 `class` 与外部样式，只有内联 `style` 存活。因此管线为：

```
markdown 原文
  → markdown-it 渲染为语义 HTML（h1-h6/p/ul/ol/blockquote/pre/code/table/a/img…）
  → 提取首个 h1 作为标题，正文包进 <article class="mly-body">
  → <style> 注入主题 CSS（全部作用域在 .mly-body 下，禁用 media query / 伪元素）
  → juice() 把所有 CSS 规则展开为元素 style 属性
  → 产出微信兼容 HTML（class 残留无害，微信会剥掉）
```

**新增依赖（主进程）**：
- `markdown-it`（MIT）核心渲染；
- `juice`（MIT）CSS 内联；
- 可选：`highlight.js`（MIT）代码高亮（批次 D）。

### A2 主题系统
新文件 `src/main/services/layout-themes.ts`，静态注册（无 DB 依赖）：

| id | 名称 | 风格 | 主色 |
|---|---|---|---|
| `wechat-green` | 微信经典 | 现有风格的精修版 | #07c160 |
| `magazine` | 杂志衬线 | 衬线标题、大字距、细分割线 | #1a1a1a |
| `tech-blue` | 科技蓝 | 冷色标题、代码块友好 | #2b6cb0 |
| `warm-paper` | 暖纸 | 米色引用块、暖棕强调 | #b4632a |
| `minimal` | 极简黑白 | 无色相、靠字重与留白 | #111111 |

每套主题 = 一段作用域 CSS（覆盖 h1-h4/p/ul/ol/li/blockquote/pre/code/table/th/td/img/a/strong/hr），风格基准参考 doocs/md（WTFPL 许可，可自由改编）后按心流口味调校。

**链接处理**：微信正文里外链不可点击。`wechat` 平台把 `<a>` 渲染为「文本 + 上标序号」，文末追加「参考链接」小节（doocs/md 的脚注法）；`web` 平台保留真实 `<a>`；`xiaohongshu` 维持纯文本强化（emoji 分段），不走进该管线。

**纯文本**：`plainText` 从 markdown-it 的 token 树生成（比现在的逐行 strip 更干净），小红书分支保留现有 `toXiaohongshu` 并补有序列表/加粗剥离。

### A3 数据与接口改动
- `article_layouts` 表新增 `theme_id TEXT`（走 `ensure*` 加列流程，无需重建）；
- `contracts.ts`：`ArticleLayout.themeId?`、`CreateArticleLayoutInput.themeId?`；新增 `LayoutThemeInfo { id, name, description, accent }`；
- IPC：`layouts:create` 接受 `themeId`（缺省 `wechat-green`）；新增 `layouts:themes` 返回主题清单；
- `sanitizeHtml` 白名单补 `sup/sub/figure/figcaption`（脚注与 juice 产物）；
- `LayoutsPage`：平台旁加主题下拉（含主题名与色点），生成时带上 `themeId`；历史排版稿显示其主题徽标。

### A4 测试与验收
- 新增 `tests/layout-renderer.test.ts`：给定含 加粗/表格/代码块/链接/图片 的样例 markdown，断言产物含 `<table`、`<pre`、`style="`（内联生效）、无裸 `**`；脚注链接含「参考链接」；
- 更新 `scripts/smoke-layouts.mjs` 断言；
- 截图验收：五套主题各出一张排版预览，judge 过目。

### A5 风险
- juice 对伪元素支持有限 → 主题 CSS 禁用 `::before/::after`（编号、装饰用真实标签）；
- `pdf`/`docx` 与本批次无关；markdown-it 默认关闭 `html:true`，防注入；
- 微信对部分 CSS 属性有白名单（如 float 支持有限）→ 主题只用 margin/padding/color/font/border/background/line-height 等安全属性。

## 批次 B：文件上传素材（约 1 天）

### B1 行为设计
素材库新增「上传文档」入口（工具栏按钮 + 拖拽可后续增强）：
- 支持 `.txt / .md`（UTF-8 直读）、`.pdf`（pdf-parse 提取）、`.docx`（mammoth 提取纯文本）；
- 单文件 ≤ 10MB；提取文本 ≤ 20,000 字符（超出截断并标注「……（已截断）」），防止撑爆下游提示词预算；
- 入库为 `kind:'text'` 素材：`title`=文件名（去扩展名），`summary`=提取文本，`sourceNote`=`文件上传 · 格式`；
- 选中选题时上传自动关联 `relatedTopicId`（与手动素材一致）。

### B2 技术改动
- 新增依赖：`pdf-parse`（MIT，注意从 `pdf-parse/lib/pdf-parse.js` 引入以绕开其调试读文件副作用）、`mammoth`（BSD-2）；
- `contracts.ts`：`MaterialOrigin` 增加 `'file_upload'`；新增 `AddFileMaterialInput { fileName; data: ArrayBuffer; relatedTopicId? }`；`MoliuApi.materials.addFile`；
- **DB 迁移**：`materials.origin` 的 CHECK 约束含旧枚举，按 `migrateReviewTasksRunning` 同款流程重建表（关外键→建新表→拷贝→改名→开外键），新 CHECK 加入 `'file_upload'`；
- IPC `materials:add-file`：zod 校验（fileName ≤ 300、data ≤ 10MB、relatedTopicId 可选）→ 按扩展名分发解析 → `addManualMaterial` 复用入库路径（origin='file_upload'）；
- `serializeMaterials`（框架/文章注入）：单条 summary > 8,000 字符时截断加省略号，控制提示词体积；
- `MaterialsPage`：工具栏「上传文档」按钮 + 隐藏 file input + busy 态 + 成功 toast；素材行 kind=text 显示来源徽标「文件」。

### B3 验收
- 单测：txt/md/pdf/docx 四种样例文件解析入库（pdf/docx 用极小样例文件）；超限截断断言；
- 实机：上传一个 pdf → 出现在素材库 → 框架生成勾选后确认提示词包含其内容片段。

## 批次 C：自动衔接三件套（约 0.5 天）

1. **选题 → 素材库搜索词预填**：选题卡「搜集素材」在现有 `moliu:material-related-topic-id` 之外写入 `moliu:material-search-query`（= 选题主题）；`MaterialsPage` 挂载读取（读即清），预填搜索框。
2. **选题 → 框架自动勾选关联素材**：`FrameworksPage` 监听 `topicId` 变化，把 `relatedTopicId === topicId` 的素材并入 `materialIds`，并显示一次性提示「已带入该选题关联的 N 条素材」。
3. **选题 → 框架账号继承**：同个监听里，若选题带 `accountIds[0]` 则自动设置账号下拉（用户可改），消除最后一处重复选择。

三处均为纯前端小改，无 schema、无新 IPC。

## 批次 D：可选增强（按需另排）

1. **文内图片自动转存微信**：推送草稿时把正文里的外链/本地图片经 `/cgi-bin/media/uploadimg` 转存并重写 `<img src>`，让带图文章真正可推送（当前外链图片微信会剔除）；
2. **代码高亮**：highlight.js + 代码主题选项（技术类账号刚需，生活类无用）；
3. **账号「选题方向/内容支柱」字段**：增强第 1 段对第 3 段的驱动（会动账号 schema 与向导，单独评估）；
4. **排版主题自定义 CSS**：允许高级用户粘贴自定义主题（数据模型已可承载，UI 另做）。

## 实施顺序与验收

**顺序**：A（排版，你点名的痛点）→ B（文件上传）→ C（衔接）→ D 按需。
**每批次收尾**：`npm run build` + vitest + 相关 smoke；A 批次额外做五主题截图 judge。
**总工作量估算**：A ≈ 1.5~2 天 · B ≈ 1 天 · C ≈ 0.5 天 · 合计约 3~3.5 天。

**回滚设计**：A 的旧排版稿数据不受影响（theme_id 为空即旧稿）；B 的表重建迁移一次性且幂等；C 全部 localStorage/前端态。
