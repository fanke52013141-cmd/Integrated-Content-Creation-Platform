# 交接：模型类型分流与每环节选厂商（2026-11-03 第二轮）

本轮两件事：功能审核发现的问题修复 + 两项能力落地（参照 free-creation 的供应商策略：一个供应商同时挂文本与生图模型；每个环节可选用不同厂商）。

## 一、功能审核发现并修复的问题

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | **混合供应商的模型串台**：供应商同时勾选文本+生图能力后，它的所有模型会同时出现在文本下拉和生图下拉（生图模型被拿去跑对话、文本模型被拿去生图） | 模型无类型概念，能力只是供应商级开关 | 模型增加 `kind: text\|image`，下拉按类型分流（本轮核心改动） |
| 2 | **一个供应商只能有一个默认模型**（`idx_provider_models_one_default` 单列唯一索引），文本默认和生图默认互斥 | 索引定义按"每供应商一个默认"设计 | 索引重建为 `(provider_id, kind)`，每类各一个默认 |
| 3 | **保存前只测一种端点**：`testAndSave` 按 `capabilities.image ? image : chat` 二选一，双能力供应商另一半端点从未验证 | 单次探测逻辑 | 挂了哪类模型就测哪类：文本默认模型走 chat 探测 + 生图默认模型走生图探测，两个都过才保存 |
| 4 | **能力勾选与模型列表可矛盾**：勾了"图片生成"但没有生图模型（或反之） | capabilities 是手填开关 | `capabilities.chat/image` 保存时由启用模型的类型派生，UI 改为派生徽标 |
| 5 | **生图环节共用一个全局默认**：配图页与智能配图共用 `moliu:default-image-model`，两处只能同厂商同模型 | 单一 localStorage 键 | 拆成 `moliu:visuals-image-model`（配图页）与 `moliu:studio-image-model`（智能配图），旧键仅作回落 |
| 6 | **存量：`test:workflow`/`test:smokes` 大面积失败**（master 上即可复现）：全新工作区首次创作引导弹窗自动打开并挡住导航，冒烟脚本没有先关它 | 引导弹窗（36845ff 落地）与冒烟脚本未同步 | `run-all-smokes` 统一走后台模式（启动器已内置引导完成标记预置）；`smoke-workflow` 增加显式关闭引导的兜底 |
| 7 | **存量：smoke-materials 整轮跑偶发超时**：连续启动多个 Electron 负载高时 30s 默认超时不够 | 未设置脚本级超时 | `setDefaultTimeout(60_000)` |

## 二、模型类型分流（free-creation 策略对齐）

- 契约：`ProviderModel.kind`、`SaveProviderModelInput.kind`（缺省视为 text，旧调用方零改动）、`ProviderPreset.modelKind`。
- 数据库：`provider_models.kind` 列（`TEXT NOT NULL DEFAULT 'text'`）；迁移 `ensureProviderModelKind()`——纯生图供应商模型全标 image；双能力供应商按 `price_per_image` 与常见生图模型名（image/dall-e/seedream/flux/…）推断；每类缺默认自动补；唯一索引重建为 `(provider_id, kind)`。
- 网关：`resolveModel` 默认回落只认 text 模型（显式指定 modelId 仍尊重调用方）；只有生图模型的供应商对话请求报"没有可用的默认文本模型"。
- IPC：zod 每类各校验一个默认；`providers:test-and-save` 双端点探测；提示词绑定校验要求绑定的是 text 模型。
- UI：「AI 服务」模型卡片新增 文本/生图 分段选择；默认 radio 按类型分组（文本默认/生图默认）；能力行改为派生徽标；「测试连接」双端点各自报告。
- 纯函数下沉 `src/shared/model-options.ts`（`availableModels` / `availableImageModels`），渲染层 `lib/models.ts` 转发导出，主进程测试可直接引用。

## 三、每环节选用不同模型厂商（现状 + 本轮补齐）

| 环节 | 选择机制 | 厂商可不同 |
|------|----------|------------|
| 账号定位 / 热点筛选 / 选题 / 框架 / 写文章 / 改稿 / 配图方案 / 配图规划 / 配图提示词 | 「提示词」页按环节绑定默认厂商+模型（随版本保存），页面进入自动带出、当次可改 | ✅ 一直支持 |
| 评审 | 每个角色可单独指定厂商+模型，未指定沿用本次评审的页面级模型 | ✅ 一直支持 |
| 配图页生图 | 独立默认 `moliu:visuals-image-model` | ✅ 本轮拆出 |
| 智能配图生图 | 独立默认 `moliu:studio-image-model` | ✅ 本轮拆出 |
| 素材搜索 | 豆包 API（非 LLM），独立密钥 | 不适用 |
| 排版 | 纯模板渲染，不调用模型 | 不适用 |

## 五、已知限制与后续建议

- 双能力供应商的旧模型类型靠启发式推断（成本字段 + 模型名），未命中的生图模型会停留在 text——用户需到「AI 服务」手动把类型改为生图；生图下拉的空态文案已指向该入口。
- `providers:test`（列表卡片上的测试按钮）对混合供应商仍只测文本端点（失败才回退生图探测）；后续可改为双端点。
- free-creation 的"本机 CLI 型供应商（OAuth 登录态、无 API Key）"与"模型白名单三层禁用"未纳入本轮，当前协议仍是 OpenAI-compatible 单一形态。
